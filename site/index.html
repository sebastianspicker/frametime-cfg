Counter-Strike 2 · x64 Windows · native Rust

See every change first. Keep the way back.

frametime.cfg inspects, plans, applies, verifies, and recovers selected CS2, graphics-driver, network, power, and Windows settings. It previews the whole sequence before it touches anything, captures what it will change, reads the result back, and restores only to the exact target it captured.

25 of its 54 steps are advice only. They leave Windows as it is and say when a change would be justified.

02

Every change carries its way back

Each supported change follows the same four clauses. If one fails, the change does not happen or is not reported as done.

  1. Authenticate

    State-changing commands run only from an authenticated, signed package. A source build, a copied executable, or an unsigned package gets the preview and nothing else.

  2. Capture

    Supported state is recorded under the fixed protected root C:\FRAMETIME_CFG before anything is written, with audit and recovery evidence.

  3. Apply, then read back

    After a write, the target is read back. Success is reported only when the readback matches.

  4. Restore to the same target

    Restore checks the exact target identity again. Incoherent state is refused, not reconstructed on a best guess.

Three boots, one sequence

  1. Phase 1 Normal boot

    38 steps

    Checks, guidance, the baseline benchmark, and preparation. Ends by publishing the exact payload into a protected runtime and arming Safe Mode.

  2. Phase 2 Safe Mode

    3 steps

    Clean GPU-driver removal, then clears Safe Boot and hands off to the same user's next normal boot.

  3. Phase 3 Normal boot

    13 steps

    Driver install, profiles and guidance, the final checklist, and the final benchmark with the FPS strategy.

A pending handoff runs only through the selected authenticated runtime. Read recovery before exercising a live package, and keep independent backups.

03

A cap needs five runs behind it

Import VProf output from CS2. A nonzero FPS cap is accepted only with at least five complete runs, and only if every unrounded P1 value reaches it. For a VRR ceiling, the cap is refresh rate minus margin.

One weak run is enough to refuse the cap. The evaluation shows each run's numbers, including the ones that fail.

Raw mode, the default, stays uncapped. The tool does not detect or enable VRR, and the refresh rate starts empty instead of guessing your monitor.

Saving a cap writes state and benchmark history, then reads both back. It does not deploy CS2 configuration, and it does not predict a performance gain.

06

What this does not claim

  • Host builds, linting, and cross-compilation do not qualify UAC, Safe Mode, drivers, NVAPI, Windows APIs, hardware, or a complete reboot sequence.
  • No universal FPS, frame-time, latency, image-quality, or stability gain. Settings depend on the CS2 build, Windows version, driver, hardware, display, and network.
  • Recovery covers only state the workflow captured and can bind to the same target. It is not a system image or a general rollback tool.
